# SUDMS — ระบบบริหารงานสารบรรณดิจิทัล

ระบบ Flask / SQLite สำหรับองค์กรนักศึกษา มหาวิทยาลัยขอนแก่น ใช้ UI สีแดง #A73B24 / #8B0000 และ Bootstrap 5

## เริ่มใช้งานใน VS Code (PowerShell)

```powershell
cd "C:\คอมปี 2\SUDMS"
# หากยังไม่มี virtual environment
py -3.13 -m venv .venv
# ไม่จำเป็นต้อง Activate จึงไม่ติดข้อจำกัด ExecutionPolicy
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m flask --app app init-admin
.\.venv\Scripts\python.exe app.py
```

เปิด http://127.0.0.1:5000 สร้างแอดมินด้วยอีเมลของเลขานุการองค์การนักศึกษาและรหัสผ่านอย่างน้อย 10 ตัวอักษร ไม่มีรหัสผ่านสำเร็จรูป สมัครผู้ใช้ผ่าน /register จากนั้นแอดมินอนุมัติที่ /admin
แนะนำ Python 3.12–3.13 เพื่อความเข้ากันได้ของ pandas; หากเครื่องใช้ Python รุ่นใหม่กว่าให้ตรวจสอบว่า pip มี wheel ของทุกแพ็กเกจ

## การทำงาน

- องค์การนักศึกษา 21 คนรวมแอดมิน 1 คน หน่วยงานอื่น 2 คนต่อหน่วยงาน ตรวจโควตาตอนอนุมัติภายในธุรกรรม SQLite; ผู้รออนุมัติไม่กินโควตา
- แอดมินเข้าถึงทุกเอกสาร ผู้ใช้เห็นเอกสารของหน่วยงานตนหรือหน่วยงานที่เคยได้รับเอกสาร; หน่วยงานผู้ถือปัจจุบันเท่านั้นที่สั่งการ/แก้ไข/อัปโหลดได้ รวมถึงแอดมิน
- หนังสือรับ/ส่งและจองเลขเรียงตามปี พ.ศ. เลขจองไม่ถูกนำกลับมาใช้และไม่ใช่การสร้างเอกสาร
- ตอบรับ ส่งต่อ สั่งการ เกษียณ ปิดงาน พร้อม Timeline และ Audit เก็บ before/after โดยไม่มี API ลบประวัติ
- แนบ PDF และ DOCX ขนาดคำขอสูงสุด 10 MB เก็บ hash SHA256 และไฟล์แยกทุกเวอร์ชัน v1.0, v1.1,...
- ถังขยะเป็น soft delete พร้อมกู้คืน ไม่ลบไฟล์หรือประวัติ
- ค้นหาชื่อเรื่อง เลขทะเบียน ผู้ส่ง สถานะ ประเภท ความเร่งด่วน และช่วงวันที่; ส่งออก Excel ตามตัวกรองที่เลือก
- แบบฟอร์มไทย/อังกฤษ PDF/Word เป็นแม่แบบตั้งต้น ไม่ใช่แบบฟอร์มทางการที่มหาวิทยาลัยรับรอง PDF ไทยใช้ Tahoma ของ Windows
- Password hash, CSRF, session cookie HttpOnly/SameSite, ตรวจสิทธิ์ไฟล์, escape ข้อความใน UI และป้องกัน Excel formula injection
- วันที่จัดเก็บเป็นเวลาไทย UTC+07:00

## REST API

ทุก API ต้องเข้าสู่ระบบ ยกเว้นหน้าเข้าสู่ระบบและสมัครสมาชิก ทุกคำขอเปลี่ยนข้อมูลต้องมี X-CSRF-Token จาก meta tag

| Method | Endpoint | การใช้งาน |
|---|---|---|
| GET/POST | /api/documents/received | รายการ/สร้างหนังสือรับ |
| GET/POST | /api/documents/sent | รายการ/สร้างหนังสือส่ง |
| GET | /api/documents/all | เอกสารทั้งหมดที่มีสิทธิ์ |
| GET | /api/documents/<id>/history | Timeline / Audit / ไฟล์ |
| POST | /api/documents/<id>/action | receive / forward / instruct / endorse / complete |
| PATCH | /api/documents/<id> | แก้ไข title / sender / content |
| POST | /api/documents/<id>/attachments | multipart file |
| GET | /api/attachments/<id>/download | ดาวน์โหลดไฟล์ที่มีสิทธิ์ |
| POST | /api/documents/<id>/trash | {restore: false/true} |
| POST | /api/numbers/received/reserve | จองเลขรับ |
| POST | /api/numbers/sent/reserve | จองเลขส่ง |
| GET | /api/reports/export | Excel ตามตัวกรอง |
| GET | /api/admin/users | ผู้ใช้ (แอดมิน) |
| POST | /api/admin/users/<id>/approval | approved / rejected / suspended |

สร้างหนังสือต้องส่ง title, sender, recipient_org_id และเลือก category, priority, content, digital_only, reservation_number ได้

## ก่อนใช้งานจริงในมหาวิทยาลัย

รุ่นนี้เป็นระบบต้นแบบใช้งานภายในที่รันบนเครื่องเดียว ก่อนเปิดบริการจริงต้องเชื่อมตัวตนมหาวิทยาลัย/ยืนยันอีเมล กำหนดสิทธิ์ผู้บริหารสำหรับการลงนาม เพิ่ม rate limiting, TLS และ WSGI production server รวมถึงสำรองฐานข้อมูลและ uploads พร้อมกัน Audit เป็นระดับแอป ไม่ใช่หลักฐานลงลายมือชื่อดิจิทัลหรือ log ป้องกันผู้ดูแลฐานข้อมูลแก้ไข
Bootstrap/Icons โหลดจาก CDN จึงต้องมีอินเทอร์เน็ต หากใช้งานในเครือข่ายปิดให้ดาวน์โหลด dependency มาเก็บใน static/vendor และปรับ layout.html / auth.html
ตั้ง SUDMS_HTTPS=1 เมื่อใช้ HTTPS และตั้ง SUDMS_SECRET_KEY ผ่าน environment สำหรับ deployment; ห้ามเผยแพร่ instance/secret.key หรือฐานข้อมูล

สภาพแวดล้อมที่ติดตั้งและทดสอบในเครื่องนี้: .venv (Python 3.12) ส่วน venv เดิมของผู้ใช้ไม่ได้ลบหรือแก้ไข

## หน่วยงานและเลขหนังสือ

ผู้สมัครแจ้งหน่วยงานที่ต้องการ เลขานุการเลือกหน่วยงานจริงก่อนอนุมัติ ระบบตรวจโควตาหน่วยงานปลายทางและบันทึกประวัติการจัดหน่วยงาน ผู้ใช้เห็นพื้นที่หน่วยงานที่อนุมัติและเอกสารที่หน่วยงานมีสิทธิ์เท่านั้น ผู้ดูแลระบบยังตรวจสอบได้ทุกหน่วยงาน

เลขหนังสือใหม่ใช้ตัวย่อหน่วยงาน + เลขอย่างน้อย 3 หลัก / ปี พ.ศ. เช่น อน.มข.001/2569, ชถภ.001/2569, CSL001/2569 เลขรับและเลขส่งใช้ลำดับร่วมกันต่อหน่วยงาน เริ่มนับใหม่ตามปี และการจองเลขกินลำดับด้วย เพื่อหลีกเลี่ยงเลขซ้ำ ระบบคงเลขเอกสารเก่า ไม่เปลี่ยนย้อนหลัง

แอดมินเปลี่ยนหน่วยงานผู้ใช้ที่อนุมัติแล้วได้จากปุ่มบันทึกหน่วยงาน สิทธิ์จะเปลี่ยนตามหน่วยงานทันที และเลขจองของหน่วยงานเก่าจะไม่สามารถใช้จากหน่วยงานใหม่

## ผู้ใช้งานและหน่วยงานสำหรับแอดมิน

หน้า /admin แสดงการ์ดครบทุกหน่วยงาน พร้อมจำนวนบัญชีทั้งหมด ผู้อนุมัติ ผู้รออนุมัติ และผู้ที่เคยเข้าสู่ระบบ เลือกหน่วยงานเพื่อดูรายชื่อ ค้นหาจากชื่อ อีเมล รหัสนักศึกษา ตำแหน่งหรือคณะ และกดดูข้อมูลเพื่อเปิดรายละเอียดรายบุคคล

รายละเอียดส่วนบุคคลรวมตำแหน่ง คณะ สาขา ชื่อภาษาอังกฤษ ชื่อเล่น โทรศัพท์ และข้อมูลสองคอลัมน์ชั้นปีที่คงตามต้นฉบับเนื่องจากไม่มีหัวคอลัมน์ระบุความหมาย

last_login_at และ login_count เริ่มบันทึกการล็อกอินสำเร็จหลังเปิดใช้เวอร์ชันนี้ ไม่ใช่สถานะออนไลน์ realtime และไม่มีการเดาประวัติย้อนหลัง เฉพาะแอดมินเท่านั้นที่เข้าถึง API รายชื่อพร้อมข้อมูลส่วนตัวได้ รหัสผ่านและ hash ไม่ถูกส่งกลับไปยังหน้าจอ

นำเข้ารายชื่อองค์การนักศึกษา 21 คนลงฐานข้อมูลของเครื่องนี้แล้ว โดยมีเลขานุการเป็นแอดมิน 1 คน บัญชีใหม่ 20 คนมีรหัสผ่านสุ่มที่ไม่ได้แจกและไม่ได้เก็บเป็น plaintext ให้ตั้งรหัสผ่านครั้งแรกผ่าน OTP หลังตั้ง SMTP บัญชีเลขานุการเดิมคงรหัสผ่านเดิมไว้ ZIP source ไม่รวมข้อมูลสมาชิก ฐานข้อมูล หรือไฟล์ตั้งค่า SMTP

หน้าสมัครเลือกคณะ/วิทยาลัยจากรายการ 22 แห่งตามที่กำหนด และเลือกหน่วยงานจาก 52 หน่วยงาน แบ่งกลุ่มองค์กร/กลุ่มกิจกรรมและชมรม Backend ตรวจคณะกับรายการที่อนุญาต ข้อมูลคณะของสมาชิกเดิมคงไว้ตามที่นำเข้า

เมื่อแอดมินบันทึกหน่วยงานสำเร็จ หน้ารายชื่อแสดง “บันทึกลงหน่วยงานแล้ว” พร้อมผู้อนุมัติและเวลาไทย ข้อมูลอ่านจาก UserApprovalLog จึงคงอยู่หลังรีเฟรช ปุ่มจะกลับมาให้บันทึกเมื่อเลือกหน่วยงานอื่น ดูข้อมูลแสดงประวัติการอนุมัติ/ย้ายหน่วยงาน/ระงับทั้งหมด ชื่อและเวลาผู้อนุมัติสร้างจากบัญชีและเวลาฝั่งเซิร์ฟเวอร์ ไม่มีการเดาประวัติที่ไม่ได้บันทึก

## แบบฟอร์มที่แนบเข้าระบบ

เพิ่มไฟล์ต้นฉบับ 11 ประเภท รวม 22 ไฟล์ PDF/DOCX ใน form_files/ และรายการกำหนดใน form_catalog.py ผู้ใช้ที่ได้รับอนุมัติและเข้าสู่ระบบดาวน์โหลดได้จากหน้าแบบฟอร์มทั่วไปผ่าน /api/forms/files/<slug>/<format> ไฟล์ไม่อยู่ใน static เพื่อให้ทุกการดาวน์โหลดผ่านการตรวจ login ส่วนภาษาอังกฤษยังเป็นแม่แบบตั้งต้น เพราะไม่ได้มีไฟล์ภาษาอังกฤษแนบมาด้วย

## หนังสือส่งฉบับปรับปรุง

กดเพิ่มหนังสือส่งเพื่อกรอกเลขหนังสือ/ปี พ.ศ. เวียน ประเภท วันที่ เรื่อง ชั้นความเร็ว (ทั่วไป/ด่วน/ด่วนมาก/ด่วนที่สุด) วันครบกำหนด เจ้าของเรื่อง ผู้รับ หน่วยงานภายในหรือภายนอก บุคลากร เรียน การปฏิบัติ หมายเหตุ ไฟล์แนบ และวิธีส่ง DIGITAL/กระดาษ พร้อมตัวเลือกส่งกระดาษภายในวันนี้

- บันทึกร่างรอส่ง: เก็บข้อมูลและแนบไฟล์โดยยังไม่เผยแพร่ไปปลายทาง สมาชิกหน่วยงานต้นทางและแอดมินดู/แก้ร่างได้
- บันทึกและส่ง: ฟอร์มบันทึกร่างก่อนอัปโหลดทุกไฟล์ แล้วจึงส่งผ่าน API หากอัปโหลดไม่สำเร็จจะคงร่างและไม่ส่งถึงปลายทาง ลิงก์เปิดร่างแสดงให้ผู้ใช้
- ส่งเข้าหน่วยงาน SUDMS: เอกสารปรากฏในกล่องรอรับของผู้รับเมื่อกดส่ง
- ส่งภายนอกหรือคณะ/วิทยาลัยที่ไม่ได้มีบัญชี SUDMS: บันทึกทะเบียนและประวัติ ไม่ได้ส่งอีเมลหรือเชื่อมระบบภายนอกอัตโนมัติ
- ลายเซ็นดิจิทัล: บันทึกวิธีส่งและแนบไฟล์ที่นำไปลงนามได้ แต่ยังไม่มีระบบเซ็นดิจิทัลในแอป
- เลขจองเป็นเลขร่วมของหน่วยงาน สมาชิกคนอื่นในหน่วยงานใช้ได้ มีชื่อและเวลาผู้จอง/ผู้ใช้เลข
- กรอกเลขเองเป็นเลขลำดับอย่างน้อย 3 หลักภายใต้รหัสหน่วยงานและปีปัจจุบัน ตรวจเลขซ้ำรวมเลขจองและเลขที่ใช้ไปแล้ว เลขที่เติมศูนย์นำหน้ามากกว่าปกติถูก normalize ก่อนตรวจซ้ำ
- เลขรับ/ส่งใช้ลำดับเดียวกันต่อหน่วยงานและปี ออกเลขอัตโนมัติต่อจากเลขสูงสุดรวมเลขที่กำหนดเอง/จองไว้ ไม่คืนเลขร่างที่ลบหรือเปลี่ยนเลขให้ใช้ใหม่
- แก้แบบฟอร์มและเปลี่ยนเลขได้ก่อนส่งในหน้ารายละเอียดร่าง ประวัติแก้ไขบันทึกก่อน/หลังพร้อมผู้ทำรายการ การส่งซ้ำของเอกสารที่ส่งแล้วถูกปฏิเสธ
- แนบ PDF/DOCX ได้สูงสุด 5 ไฟล์ต่อการบันทึก ฟอร์มจำกัดไฟล์ 9.8 MB เพื่อให้ request รวมไม่เกิน 10 MB ไฟล์เดิมและเวอร์ชันก่อนยังอยู่

API เพิ่ม: GET /api/numbers/sent/details (ประวัติเลขทั้งหน่วยงาน), POST /api/documents/sent รองรับ save_mode=draft/send, number/reservation_number, send_details; POST /api/documents/<id>/action รองรับ action=send สำหรับร่างเท่านั้น

เปิด RESTART-SUDMS.cmd เพื่อรีสตาร์ตตัวเปิดล่าสุดบนพอร์ต 5056 จากนั้นเข้าหนังสือส่ง เพิ่มหนังสือส่ง หรือเลือกเอกสารสถานะร่างเพื่อแก้ไข/แนบไฟล์/ส่ง

## รายการจองเลขในทะเบียนหนังสือส่ง

เมื่อกดจองเลขทะเบียน (หนังสือส่ง) ระบบสร้างรายการจองในทะเบียนทันที แสดงเลขส่ง ถึง เรื่อง วันที่หนังสือ แก้ไข ติดตาม และส่ง พร้อมป้ายจองและชื่อผู้จอง กดเลข/ชื่อหรือไอคอนดินสอเพื่อเปิดฟอร์มร่างอัตโนมัติ กรอกข้อมูลแล้วเลือกบันทึกร่างหรือบันทึกและส่งได้โดยใช้เลขเดิม ไม่สร้างเอกสารซ้ำ

รายการจองยังไม่ถูกส่งไปปลายทาง และปุ่มส่งยังไม่เปิดใช้ก่อนกรอกข้อมูล เมื่อแก้ข้อมูลแบบฟอร์มแล้วป้ายจองเปลี่ยนเป็นร่างรอส่ง และส่งจากหน้ารายละเอียดหรือไอคอนส่งในทะเบียนได้ สมาชิกหน่วยงานเดียวกันแก้ไขได้ตามสิทธิ์ ปลายทางจะเห็นหลังส่งเท่านั้น

เลขจองก่อนเพิ่มฟังก์ชันที่ยังไม่ได้ใช้ในเครื่องนี้ถูกนำมาแสดงเป็นรายการที่แก้ไขได้แล้ว โดยคงเลข ชื่อผู้จอง และเวลาจองเดิมไว้ การเลือกเลขจองในฟอร์มเพิ่มหนังสือส่งจะใช้รายการเดิม มีประวัติจอง/แก้ไข/ส่งพร้อมผู้ดำเนินการ

หน้าแก้ไขหนังสือส่งใช้ /documents/<id>/edit แสดงฟอร์มเต็มเหมือนเพิ่มหนังสือส่ง เติมเลขเดิมและข้อมูลเดิมให้อัตโนมัติ รองรับข้อมูลเก่าที่ไม่มี send_details โดยไม่เกิด Jinja UndefinedError เลขจองแสดงช่องเรื่องว่างให้กรอกจริง ผู้ใช้เลือกบันทึกร่าง/บันทึกและส่งได้ ไม่สร้างเอกสารใหม่ สิทธิ์ยังตรวจหน่วยงานผู้ถือหรือแอดมิน เปิดผ่าน URL เดิม ?edit=1 ได้เช่นกัน ข้อผิดพลาดฝั่งเซิร์ฟเวอร์เก็บที่ instance/app-errors.log

## ผู้รับหลายหน่วยงาน ช่องไม่บังคับ และรหัสเวียน

บุคลากร ผู้รับเอกสาร/หนังสือ การปฏิบัติ หมายเหตุ และหน่วยงานภายใน/ภายนอกไม่บังคับ ส่งโดยไม่ระบุผู้รับได้เป็นบันทึกทะเบียนส่ง หน่วยงานภายในเลือกหลายรายการด้วย Ctrl/Shift และเพิ่มชื่อหน่วยงานภายในอื่นได้ หน่วยงานภายนอกและรายชื่อผู้รับเพิ่มแถวได้ไม่จำกัด ไม่มีเพดานจำนวนรายการในฟอร์มหรือ API ระบุภายใน/ภายนอกร่วมกันได้ รายการซ้ำถูกตัดออก

หน่วยงานภายในที่มีบัญชี SUDMS ทุกหน่วยงานที่เลือกจะได้รับสิทธิ์เอกสารและมีสถานะ pending/received/in_progress/completed แยกกันใน DocumentRecipient การรับหรือปิดงานของหน่วยงานหนึ่งไม่ล้างกล่องรอรับของหน่วยงานอื่น การส่งหน่วยงานที่ไม่มีบัญชีและภายนอกยังเป็นการบันทึกทะเบียน ไม่ส่งอีเมลอัตโนมัติ

เลือกเวียนเปลี่ยนรหัสนำหน้า เช่น อน.มข. เป็น อน.มข.ว. ตัวอย่าง อน.มข.ว.001/2569 มีทั้งการออกเลขอัตโนมัติ จองเลขเวียน กรอกเลขเอง และเปลี่ยนเลขร่างเดิมเป็นเวียน ร่างยังคงเลขลำดับเดิมและมี Audit ของรหัสก่อน/หลัง เลขปกติและเลขเวียนใช้ลำดับร่วมกันต่อหน่วยงานและปี

หน้ารายละเอียดไม่มีส่วนบันทึกการดำเนินการและเอกสารแนบ/เวอร์ชันแล้ว ประวัติการทำรายการยังถูกบันทึกอัตโนมัติในระบบ และแนบไฟล์ได้ในฟอร์มเพิ่ม/แก้ไขหนังสือส่ง


## แบบฟอร์มภาษาอังกฤษ
เพิ่มไฟล์ต้นฉบับ 4 ประเภท รวม 8 ไฟล์ PDF/Word ในแท็บแบบฟอร์มภาษาอังกฤษ รวมทั้งระบบ 15 ประเภท 30 ไฟล์ หากเซิร์ฟเวอร์เดิมยังเปิดอยู่ ให้ใช้ RESTART-SUDMS.cmd และเปิดหน้าดาวน์โหลดใหม่


## การรับเอกสารและพื้นที่ส่วนตัว
หนังสือรอรับมีปุ่มลงทะเบียนรับเอกสาร ปลายทางกรอกเรียน การปฏิบัติ หมายเหตุ และเลือกสมาชิกผู้รับผิดชอบได้ ระบบสร้างทะเบียนรับใหม่พร้อมเลขรับของปลายทาง อ้างอิงเลขและไฟล์ต้นทางโดยไม่เปลี่ยนเลขหนังสือส่ง สมาชิกหน่วยงานเห็นเอกสารร่วมกัน ส่วนพื้นที่ส่วนตัวแสดงรายการที่ได้รับมอบหมาย หน้าสรุปหน่วยงานอยู่ที่ /admin/organizations หน่วยงานอื่นรับได้ 5 คน องค์การนักศึกษา 21 คน การกู้คืนที่เลขเดิมถูกใช้แล้วจะออกเลขใหม่พร้อมประวัติเลขเดิม


## แก้ไขหลังส่งและห้องประชุม
หน่วยงานต้นทางและแอดมินแก้ข้อมูลและเพิ่มไฟล์แนบหลังส่งได้ มี audit log โดยไม่เปลี่ยนเลขทะเบียนหรือหน่วยงานที่จัดส่งไปแล้ว เส้นทางเอกสารเลือกกรองแต่ละปลายทางได้ เมนูปฏิทินห้องประชุมอ่านตารางรายวัน KKU และแสดงคำขอ SUDMS ที่รออนุมัติหรืออนุมัติแล้ว ปฏิทิน SUDMS เก็บในฐานข้อมูลเว็บ ไม่เชื่อม Google Calendar มีตัวเลือกเดือน ห้อง และวันที่ แคชข้อมูล KKU ไม่เกิน 5 นาที ไม่ส่งคำขอแก้ไข/จองไปยังเว็บไซต์ KKU การไม่พบรายการไม่ใช่การรับรองห้องว่าง


## ใช้งานบน Android / iPhone
เว็บรองรับจอมือถือ เมนูพับ ตารางเอกสารแบบการ์ด และปฏิทิน 7 วันต่อแถว เชื่อมโทรศัพท์กับ Wi-Fi เดียวกับคอมพิวเตอร์ แล้วเปิด START-SUDMS-MOBILE.cmd บนคอมพิวเตอร์ เปิด URL http://<IP ของคอมพิวเตอร์>:5056/login ที่โปรแกรมแสดงใน Chrome หรือ Safari เปิดหน้าต่างเซิร์ฟเวอร์ไว้ ระบบนี้สำหรับเครือข่ายเดียวกัน การเข้าจากอินเทอร์เน็ตต้องติดตั้งโฮสต์และ HTTPS แยกต่างหาก ไม่ใช้ 127.0.0.1 บนมือถือเพื่อเข้าคอมพิวเตอร์

## การเข้าสู่ระบบและการยืนยันตัวตนล่าสุด

- เข้าสู่ระบบด้วย KKU-Mail รหัสนักศึกษา และรหัสผ่านที่ตรงกับบัญชีเดียวกัน
- บัญชีที่แอดมินเพิ่มสามารถกำหนดรหัสผ่านเริ่มต้น 10–128 ตัวอักษรได้ หากเว้นว่าง ผู้ใช้ที่ได้รับอนุมัติสามารถกำหนดรหัสผ่านครั้งแรกผ่านหน้าเข้าสู่ระบบ เมื่ออีเมลและรหัสนักศึกษาตรงกับบัญชี โดยครั้งถัดไปต้องใช้รหัสผ่านที่ตั้งไว้
- ลืมรหัสผ่านจะแจ้งเมื่อไม่พบบัญชี หรือบัญชียังไม่อนุมัติ และส่งรหัสยืนยันอีเมลให้เฉพาะบัญชีที่ใช้งานได้
- ต้องตั้งค่า SMTP ก่อนส่งอีเมลจริง ตาม SMTP-SETUP.md
- ปุ่มส่ง OTP เบอร์มือถือยังไม่สามารถส่ง SMS ได้ เพราะยังไม่มีผู้ให้บริการ เบอร์ถูกบันทึกว่าไม่ได้ยืนยัน ไม่สร้าง OTP จำลองหรืออ้างว่ายืนยันแล้ว

## การแสดงเลขหนังสือ

เลขหนังสือส่ง รับ และเอกสารประเภทอื่นไม่เติมศูนย์นำหน้า เช่น อน.มข.1/2569 หรือ อน.มข.ว.10/2569 เอกสารลงรับแสดงเลขทะเบียนรับของหน่วยงานและเลขหนังสือส่งของต้นทางแยกกัน เลขเดิมที่มีศูนย์นำหน้าจะถูกตัดศูนย์เฉพาะการแสดงผล โดยคงความสัมพันธ์และข้อมูลประวัติไว้
